# orbit.ops — 총무 업무 포털

구두·메신저 요청을 총무 담당자가 대신 등록하고, 처리 상태와 메모를 기록하는 첫 버전입니다. 예시 실적을 섞지 않고 빈 업무 목록으로 시작합니다.

## 실행

Node.js 24 이상이 필요하며 외부 패키지는 없습니다.

```sh
cd /workspace/kpi
npm start
```

기본 주소는 `127.0.0.1:3000`입니다. 데이터는 `data/orbit.sqlite`에 저장되어 서버 재시작 뒤에도 유지됩니다. `DATA_DIR`, `HOST`, `PORT`로 변경할 수 있습니다. 테스트는 `npm test`입니다.

## 공유할 때

기본 실행은 로그인 없는 로컬 개발 모드입니다. 외부에 공개하기 전에 `ADMIN_PASSWORD`, `VIEWER_PASSWORD`를 안전한 런타임 환경변수로 공급하고 HTTPS를 제공하는 프록시 뒤에서 실행하세요. 비밀번호를 소스에 쓰지 마세요. 계정명 `admin`은 등록·변경, `viewer`는 조회 전용입니다. 팀장에게는 viewer 계정을 제공합니다. 이는 초기 공유용 HTTP Basic 인증이며 실제 조직 운영에는 개인별 SSO와 권한 관리가 필요합니다. 관리자 비밀번호 없이 HOST를 외부 주소에 바인딩하지 마세요.

## 기록과 제한

- 요청 시각은 한국 시간으로 입력하고 등록 시각은 서버가 자동 기록합니다.
- 상태 변경·메모는 서버 DB에 누적되며 API에는 이력 수정·삭제 기능이 없습니다. DB 트리거도 이력 수정·삭제를 막습니다.
- 완료 업무 재개에는 사유가 필요합니다. 업무 원문 수정·삭제는 첫 버전에서 제공하지 않습니다. 정정은 메모로 남깁니다.
- DB/서버 관리 권한 소유자의 조작까지 막는 외부 감사 시스템은 아닙니다. 인사평가용 증빙 강화를 위해서는 개인 인증, 별도 감사 저장소, 백업·보존 정책과 관리자 권한 분리가 추가로 필요합니다.
- 현재 팀장 조회와 CSV 내보내기를 지원합니다. 첨부파일, 확인·댓글, 월별 기간 필터, AI 요약, 실제 배포는 후속 범위입니다. AI 기능이 이미 연동된 것처럼 표시하지 않습니다.
- 실적 화면은 전체 누적 기준입니다. 평균 소요 시간은 현재 완료 상태인 업무의 요청 시점부터 최종 완료까지이며 대기·주말을 포함합니다.
- SQLite 파일이 있는 디스크는 영속 저장소여야 합니다. Vercel 서버리스 파일시스템에 그대로 배포하는 구조가 아닙니다. 운영 전 영속 볼륨을 갖는 Node 서버 또는 관리형 DB로 배포해야 합니다.

환경은 작업별로 격리되어 있으므로 기존 체크아웃을 사용하고 별도 Git worktree를 생성할 필요가 없습니다.
