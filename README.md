# orbit.ops — 총무 업무 포털

총무 담당자가 구두·메신저 요청을 대신 접수하고 상태, 처리 메모, 변경 이력을 쌓는 포털입니다. 예시 실적 없이 빈 목록으로 시작합니다. 업무 보드·검색·CSV·누적 실적·팀장 조회 계정을 지원합니다.

관리자는 오른쪽 위 ⚙ 설정에서 포털 문구·메뉴·배너·업무 선택 항목·이미지 로고·색상을 관리할 수 있습니다. DB 공통 저장, 수정 전후 이력, 동시 수정 충돌 검사를 지원합니다. 운영 DB에 `supabase/settings.sql`을 한 번 실행해야 합니다. 로컬 SQLite는 시작 시 자동 준비됩니다. 설정과 이력 API는 관리자만 변경/조회하며, 팀장 계정에는 표시용 설정만 읽을 수 있게 허용합니다. 업무의 상태 단계와 보안 설정은 이 편집 대상에 포함하지 않습니다.

## 로컬 개발

Node.js 24 이상이 필요합니다. 서버 런타임은 외부 패키지 없이 동작하고, 업무 보드는 Claude Board의 Svelte 컴포넌트를 수정해 사용합니다.

```sh
cd /workspace/kpi
npm start
```

기본은 `127.0.0.1:3000`이며 로그인 없는 로컬 개발 모드입니다. 로컬 데이터는 `data/orbit.sqlite`에 보존됩니다. `npm test`는 SQLite API 흐름과 배포 설정 검증을 실행합니다.

## Claude Board 기반 업무 화면

`ko-itbuddy/claude-board` 커밋 `b81c3c149692f855c5e2fcce44a120e2367ce4a3`의 실제 `Icon.svelte`, `StateIcon.svelte`, `GroupCard.svelte`와 상태/시간 로직을 가져와 웹 총무 업무용으로 수정했습니다. 출처와 변경 내역은 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)에 있습니다. PC 터미널·Tauri 백엔드는 웹 포털 API로 교체했습니다.

- 업무 분류·부서·접수 경로별 카드, 접수 우선 정렬
- 상태별 필터와 전체 내용 검색, 카드 접기, 완료 업무 펼치기
- 간략 보기, 직접 새로고침, 기존 상세 화면의 처리 메모·상태 변경 연동

프런트엔드 소스는 `frontend/src/`입니다. 수정 후 `npm run build`로 잠금 파일에 맞춰 개발 도구를 설치하고 `public/board/` 번들과 라이선스 고지를 다시 생성하세요. 생성물을 Git에 포함하므로 기존 Render Build Command를 바꾸지 않아도 배포됩니다. 실행 시 npm 패키지나 유료 AI API는 필요하지 않습니다. 자동 주기 호출은 하지 않으며 다른 사람의 최신 변경은 새로고침으로 가져옵니다.

브라우저 검증은 별도 설치한 `playwright-core` 모듈 경로를 `ORBIT_PLAYWRIGHT_PATH`로 지정해 실행합니다. 기본 테스트에서는 명시적으로 skip합니다. Chromium 기본 경로는 `/usr/bin/chromium`이며 `CHROMIUM_PATH`로 변경할 수 있습니다.

## 무료 운영 배포

**Render Free 서버 + Supabase Free PostgreSQL**을 사용합니다. 유료 디스크는 사용하지 않습니다. 전체 절차와 환경변수는 [DEPLOY.md](DEPLOY.md)에 있습니다. `render.yaml`은 무료 플랜과 필요한 변수를 명시합니다. 실제 서비스 연결 및 배포는 계정 생성 후 수행해야 합니다.

- `STORAGE_BACKEND=supabase`로 외부 DB를 선택합니다. 배포 환경은 관리자·조회 비밀번호와 DB 연결이 필수입니다.
- 로그인은 초기 버전의 HTTP Basic 인증입니다. HTTPS에서 `admin`은 변경, `viewer`는 조회만 허용합니다. 개인별 SSO는 아직 없습니다.
- `SUPABASE_SECRET_KEY`는 서버에만 두고 클라이언트나 Git에 넣지 않습니다.
- 등록·상태 변경·메모는 DB 함수에서 트랜잭션으로 저장합니다. 변경 이력 테이블의 수정·삭제를 트리거로 막고 공개 API 키의 RPC 호출을 차단합니다.
- Supabase 연결 오류 시 로컬 저장으로 전환하지 않습니다. 운영 데이터가 임시 디스크에서 사라지는 문제를 방지합니다.

## 기록과 기능 범위

요청 시각은 한국 시간으로 입력하고 등록·변경 시각은 서버/DB에서 기록합니다. 완료 후 재개 사유가 필요합니다. 업무 원문 수정 대신 메모로 정정합니다. 실적은 누적 기준, 소요 시간은 대기·주말을 포함한 요청부터 최종 완료까지의 시간입니다.

담당자 배정, 최초 배정 시각, 첨부파일, 월별 지표·보고서 발행, 개선 이력 대장을 제공합니다. 자동 분류·유사 업무·보고서 초안은 규칙 기반이며 생성형 AI, 팀장 승인·댓글, 개인별 인증은 포함하지 않습니다. DB 관리자 권한 소유자의 변경까지 막는 외부 감사 시스템은 아닙니다. 무료 플랜에는 용량·유휴 중지 등 제한이 있어 실제 운영 전 공급자 조건과 백업 방식을 확인해야 합니다.

## PostgreSQL 계층 검증

기본 테스트는 외부 DB 테스트를 명시적으로 skip합니다. `@electric-sql/pglite`를 별도 테스트 위치에 설치하고 그 모듈 경로를 `ORBIT_PGLITE_PATH`로 지정하면 실제 PostgreSQL 호환 엔진에서 스키마 재실행, 공개 권한 차단, RPC 어댑터, 이력 보호, 트랜잭션 롤백을 검증합니다. 이는 실제 Supabase 클라우드 연결 검증을 대체하지 않습니다.

각 작업의 기존 격리 체크아웃을 사용하며 별도 Git worktree는 필요하지 않습니다.

## 업무 삭제와 휴지통

관리자는 접수·진행 중·대기·완료 여부와 무관하게 상세 화면의 **업무 삭제**로 휴지통에 이동할 수 있습니다. 삭제 사유는 필수입니다. 삭제한 업무는 일반 조회·통계·CSV에서 제외되며 viewer는 삭제 업무를 조회하거나 휴지통에 접근할 수 없습니다.

오른쪽 위 **휴지통**에서 복원하거나 제목을 정확히 입력해 영구 삭제할 수 있습니다. 복원은 이전 상태·완료 시각·처리 이력을 유지합니다. 영구 삭제는 DB의 업무 행과 처리 이벤트를 모두 제거합니다. 별도 최소 감사 기록(업무 ID·계정·시각·작업·사유)은 삭제하지 않으며, 이 기록에 업무 제목·본문을 복제하지 않습니다. 공용 admin 계정이므로 개별 사람을 식별하지 않습니다.

운영 Supabase에는 `supabase/deletion.sql`을 한 번 실행해야 합니다. 기존 업무를 일괄 삭제하지 않는 추가 마이그레이션이며 재실행 가능합니다. 새 DB는 schema.sql → settings.sql → deletion.sql 순서입니다. 로컬 SQLite는 시작 시 자동으로 삭제 열과 감사 테이블을 준비합니다. 이 코드는 기존 테스트 업무를 자동으로 삭제하지 않습니다.

## KPI 수행 기능

- 상세: 담당자 배정·최초 배정 시각, 파일 업로드/다운로드/삭제, 실제/테스트 업무 구분
- 대시보드: 실제 업무의 월간 접수·완료·기한 준수·평균 경과시간, 활성 화면에서 30초 갱신
- 업무 실적: 월 선택, 준수율 분모 표시, 평균·중앙값, 기한 도래 현황, 지표 CSV, 무료 자동 초안, 검토 후 발행·PDF 다운로드
- 개선 이력: MVP/실사용/정착 단계, 시연·피드백 출처, 개선 전후, 검증 결과, 버전 이력과 CSV
- 무료 자동화: 등록 폼에서 분류 추천 확인·적용, 실제 업무의 유사 사례 검색

**운영 DB에는 `supabase/upgrade.sql` 전체를 한 번 실행하세요.** 기존 업무를 보존하는 누적 업그레이드입니다. 최초 설치도 이 파일 한 번으로 가능합니다. 원본 SQL 변경 후 `node scripts/build-upgrade.js`로 누적본을 재생성합니다 (`npm run build`에도 포함).

지표 정의·KPI 산출물 대응·시연/검증 절차·제약은 [KPI_GUIDE.md](KPI_GUIDE.md)에 있습니다. 첨부는 DB 저장 방식으로 파일당 1MB, 업무당 10개입니다. 팀 전용 접근은 기존 공용 admin/viewer 비밀번호 관리 방식이며 개인별 소속 인증은 아닙니다. 발행본에 직접 입력한 개인정보는 업무 삭제와 별개로 보존되므로 주의해서 작성하세요.

## PDF 발행본

발행 이력의 내려받기는 A4 PDF를 브라우저에서 생성합니다. 제목·발행일·발행자·섹션별 본문·쪽 번호를 정렬하고 한글 글꼴을 PDF에 포함합니다. 별도 원시 집계값 JSON은 문서에 추가하지 않습니다. 기존 발행본에도 적용되며 DB의 원래 집계값/문안은 변경하지 않습니다. 외부 변환 서비스나 서버 Chromium은 필요하지 않습니다.

PDF 소스는 `frontend/src/report-pdf.js`, 번들은 `public/pdf/report-pdf.js`입니다. `npm run build`로 재생성합니다. 글꼴은 `public/fonts/`와 OFL 고지를 보존하세요. `ORBIT_PDF_CHECK=1` 테스트는 pdfinfo/pdftotext가 설치된 검증 환경에서 한글 추출·A4·긴 문안의 페이지 나눔·집계값 미포함을 확인합니다. 이 도구들은 실제 서비스 실행에는 필요 없습니다.
