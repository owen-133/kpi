# Next.js 이식 계획

기존 포털(루트의 Node 서버와 `public/`)의 화면·기능을 `web/` 의 Next.js 헥사고날 앱으로 옮긴다. 이 문서는 이식의 단일 계획서이고 규칙은 `AGENTS.md` 가 소유한다(여기서 다시 적지 않는다). 요구사항은 `docs/ssot/requirements.md` 의 번호로만 가리킨다.

## 1. 불변 조건

- **기존 화면·기능이 그대로 유지된다.** 이식한 화면은 기존 화면과 같게 보이고 같게 동작해야 한다. 판정은 화면 하나씩이고, 같다고 판정하는 것은 사람과 메인 세션이다(워커가 아니다).
- 기존 포털은 `render.yaml` 의 기본 배포로 남고, 전환은 사용자가 승인한 커밋에서만 한다.
- 새 보드는 기존 보드 UI 소스를 열지 않고 새로 쓴다. 기존 보드 UI 는 Apache-2.0 오픈소스에서 파생된 코드라 새 UI 를 만드는 사람이 그 파일을 열거나 복사하지 않는다(경로 목록은 「새로 쓰는 UI 의 규칙」 절에 있다).
- 외부에 보이는 것(README·PR·화면 문구·배포)은 사용자 승인 없이 바꾸지 않는다. 변경은 새 브랜치와 PR 로만 반영한다. Git 이력은 다시 쓰지 않는다.

## 2. 대상 구조

컨텍스트(`web/src/<컨텍스트>/`)와 소유 요구사항:

| 컨텍스트 | 요구사항 |
|---|---|
| `access` | R-007~R-010 (인증·역할·출처·시작 거부) |
| `request` | R-001~R-006, R-026, R-027, R-031, R-033 날짜 규칙 |
| `assignment` | R-020, R-021 |
| `attachment` | R-015 |
| `report` | R-013, R-017, R-022~R-024 |
| `improvement` | R-025 |
| `settings` | R-028, R-029 |
| `automation` | R-030 |
| `board` | R-011, R-033, R-034 (순수 묶음 도메인 + 화면) |
| `portal` | R-032 (껍데기·메뉴·브랜딩) |

- **구동 어댑터**: `app/api/[...path]/route.ts` 한 개가 기존과 같은 순서로 검사한다(인증 → 조회 권한 → 출처 → 본문 한도 → 경로 → 404 → 405, 던져진 오류는 일반 503). 서버 액션은 쓰지 않는다(조회 계정이 검사를 우회한다).
- **페이지 인증**: `src/proxy.ts` 가 `_next/static` 까지 포함해 모든 경로를 인증한다. 핸들러도 스스로 확인한다.
- **상태 관리**: TanStack Query 하나만 서버 상태에 쓴다(`staleTime: Infinity`, 포커스·재연결 재조회 없음, 재시도 없음, 자동 갱신 없음). 화면 상태는 `useReducer`. 상태 라이브러리는 `adapter/in/web` 안에서만 쓰고 `architecture.spec.ts` 가 강제한다.
- **PDF·CSV**: 기존처럼 브라우저에서 만든다. 스타일은 CSS Modules.
- **개발 저장소**: PGlite. 운영은 Postgres.
- **데이터**: 기존 `orbit_private` 의 테이블과 함수를 그대로 쓴다. 새 스키마나 데이터 이전은 없다. 쓰기 방식(함수 호출 우선, 앱 역할에는 함수 실행 권한만)은 「보안 필수 조건」 절의 첫 항목이 정한다.

## 3. 비교 방식

- **HTTP 비교**: 기존 서버(Supabase 모드, PGlite)와 새 앱에 같은 요청 순서(골든 요청 + 특성 시험 시나리오)를 보내 상태·헤더·JSON 을 정규화해 비교한다.
- **화면 비교**: `node scripts/compare-screens.mjs --screen <id>` 가 기존과 새 화면을 데스크톱(1440×1050)·모바일(390×844), 관리자·조회, 빈·채워진 상태로 찍어 픽셀과 화면 구조를 비교하고 `scratch/compare/<id>/side-by-side.html` 을 만든다. 메인 세션이 이미지를 보고 `verdict.md` 를 쓴 뒤 사용자에게 보여 드리고 승인받아야 다음 화면으로 간다. 허용 오차: 화면 구조는 완전 일치, 픽셀 차이는 보드 외 0.5%·보드 3%.
- 화면 순서: 관리자 설정 → 휴지통 → 개선 이력 → 업무 실적·PDF → Overview → 등록 → 상세 → 수정 → 업무 보드(CSV 포함).

## 4. 새로 쓰는 UI 의 규칙(클린룸)

기존 보드 UI 는 Apache-2.0 오픈소스에서 파생됐다. 새 UI 를 만드는 사람은 다음을 열거나 복사하지 않는다: `frontend/**`, `public/board/**`, `public/favicon.svg`, `public/THIRD_PARTY_NOTICES.txt`, `public/CLAUDE_BOARD_LICENSE.txt`, `THIRD_PARTY_NOTICES.md`, `third_party/**`. 입력은 `test/behavior/` 의 동작 기록, 요구사항 정본, 현재 화면을 브라우저로 본 관찰뿐이다. 아이콘은 새로 그린다. 새 화면이 승인되면 위 경로와 관련 문구를 지우고 흔적 검색(`/usr/bin/grep -rIilE --exclude-dir=.git --exclude-dir=node_modules --exclude-dir=graft --exclude-dir=.next '<상표·컴포넌트 이름들>' .`)이 아무것도 내지 않아야 한다.

## 5. 보안 필수 조건

- 기존 DB 함수(보안 정의자 함수)를 버리고 테이블을 직접 쓰는 방식은 그대로 허용하지 않는다. 우선안은 함수를 Drizzle 로 호출하고, 앱 전용 역할에 함수 실행 권한만 주고 테이블 권한은 주지 않는 것이다. 직접 쓰기를 유지하면 소유자가 아닌 역할, 이력 테이블은 SELECT·INSERT 만, TRUNCATE·TRIGGER·CREATE 금지, 정책 명시, 삭제는 정의자 함수 하나만 해야 한다. 권한 SQL 은 사용자가 실행한다.
- 운영 DB 접속은 TLS 를 강제하고(`ssl` 검증, 없으면 시작 거부), 비밀 값은 서버 전용 모듈에만 둔다.
- 인증·역할 검사는 프록시, 핸들러, 응용 계층에서 반복한다. 자격 증명 비교는 해시 비교(`timingSafeEqual`)이고 두 역할을 항상 모두 계산한다.
- 보안 헤더는 프록시에서 모든 응답(401·403·404·413·503 포함)에 붙인다: nonce 기반 CSP, HSTS, `nosniff`, `frame-ancestors 'none'`, `Referrer-Policy: no-referrer`, 인증된 응답 `Cache-Control: no-store`, `poweredByHeader: false`.
- 본문은 스트림으로 읽어 상한을 넘으면 중단한다(전체를 읽은 뒤 검사하지 않는다). 개발·운영 서버는 `127.0.0.1` 에 바인딩한다.
- DB 오류가 개인정보를 로그에 남기지 않게 오류 경계에서 걸러낸다. 로그에는 경로·상태·오류 이름만 쓴다.
- 의존성은 정확한 버전으로 고정하고 `npm audit` 을 `verify` 에 넣는다.
- 필수 시험: 모든 경로 × {무인증, 틀린 비밀번호, 조회, 관리자} 권한 행렬, 조회 계정의 쓰기가 행 수를 바꾸지 않음, 출처 검사, 본문 한도(청크 전송), 헤더 스냅샷, DB 오류 속 표식 값이 로그에 없음, 앱 역할로 이력 변경·`TRUNCATE`·`DISABLE TRIGGER` 가 실패, CSV 수식 입력, 업로드 경계, 번들에 비밀 이름 없음.
- 사용자 승인이 필요한 변화: HTTP Basic 을 세션·SSO 로 바꾸기, 로그인 실패 횟수 제한·최소 비밀번호 길이, 앞 공백 CSV 수식 방어 통일, 업로드 내용 검사.

## 6. 단계

| 단계 | 내용 |
|---|---|
| W0 | 동작 기록(`test/behavior/`), 화면 비교 도구, HTTP 비교 도구, 보안 검토 |
| W1 | 기반(프록시·가드·접속·헤더·시작 거부), 껍데기, 업무 핵심 API |
| W2 | 수정·삭제·복원, 담당·첨부, 설정·자동 분류, 개선 이력, 보고서 API, 보안 시험 |
| W3 | 보드 도메인(오웬의 시험 사례가 기준) |
| 화면 | 한 화면씩 비교·승인 |
| 전환 | 배포 PR 초안(사용자 승인, 보안 재검토) |
| 제거 | Claude Board 흔적 삭제와 흔적 검색 확인, 스냅샷 재작성은 별도 승인 커밋 |

단계마다 `node scripts/verify.mjs --base origin/<기준 브랜치>` 가 통과해야 병합한다.
